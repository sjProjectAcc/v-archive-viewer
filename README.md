# V-LOG

V-LOG는 DJMAX RESPECT V의 V-ARCHIVE 기록을 조회하고 분석하는 비공식 도구입니다. 닉네임으로 기록을 조회하고 RATE 순위, 산포도, 사용자 비교, 성장 기록과 성과 이미지를 확인합니다.

[웹앱 열기](https://sjprojectacc.github.io/v-archive-viewer/) · [정식 다운로드](https://github.com/sjProjectAcc/v-archive-viewer/releases/latest) · [TEST 다운로드](https://github.com/sjProjectAcc/v-archive-viewer/releases/tag/test-latest)

문서 확인일: 2026-10-13. 정식 버전은 `v0.1.52`이며, 아래에서 TEST로 표시한 기능은 정식판에 아직 통합되지 않았습니다. TEST는 앱 옆의 `TEST.txt`와 빌드 번호로 구분합니다.

## 주요 기능

- 닉네임별 4B, 5B, 6B, 8B 기록 조회
- 기록 표의 버튼·패턴·검색 필터와 열 정렬
- RATE에서 LogPower, POINT, DJPower 순위 선택
- Floor x Score, scorePoint, logPower, Point, DJPower 산포도
- floor별 최고점, 평균, 최저점과 최대치선
- 두 사용자의 공통 기록에 대한 Score·LogPower·POINT 비교
- Top30 및 floor 통계 공유 이미지 생성
- 데스크톱 앱의 로그인 기반 기록 히스토리 수집
- 브라우저 IndexedDB 기반 로컬 캐시
- 데스크톱 자동 업데이트 확인 및 설치

## 처음 사용하기

1. 웹앱을 열거나 Windows ZIP을 압축 해제한 뒤 실행 파일을 실행합니다.
2. 닉네임을 입력하고 새로고침합니다. 4B·5B·6B·8B 기록을 조회합니다.
3. 기록, RATE, 산포도 또는 사용자 비교에서 필요한 조건을 선택합니다.
4. 성장 기록은 데스크톱 앱에서 조회 계정에 해당하는 `account.txt`를 연결한 뒤 히스토리를 수집합니다.

일반 새로고침은 마지막 수집 시점 이후의 기록을 기존 캐시에 합칩니다. 전체 새로고침은 전체 기록을 다시 요청하므로 누락이나 불일치가 의심될 때 사용합니다. 새로고침 과정에서는 최신 전체 곡 목록도 확인해 floor·level 변경을 반영합니다.

## 화면과 계산 기준

| 화면 | 주요 내용 |
| --- | --- |
| 종합 | 전체 버튼 기록 수, Tier, DJClass, LogPower TOP50, 오류 |
| 기록 | 곡별 기록과 필터·정렬 |
| RATE | 버튼별 LogPower·POINT·DJPower 순위 |
| 산포도 | floor × Score/scorePoint/LogPower/POINT, MaxDJPower × DJPower |
| 사용자 비교 | 공통 title·button·pattern 기록과 두 계정의 수치 비교 |
| 성장 기록 | 수집한 히스토리로 복원한 시간별 합계 |
| 성과 카드 | 이전 기록과 새 기록 비교, 여러 성과를 PNG로 출력 |
| 행이봇_traits | 버튼별 SC 채보 특성 필터·정렬 |
| 계산기 | 점수 계산과 목표값에서 Score 역산 |

LogPower는 Score를 로그 함수로 변환한 뒤 floor 상수와 버튼 정규화를 적용합니다. 일반 관계값은 `0.9`이고 `99.9` 이상은 동일한 최대값으로 처리합니다. 버튼별 이론상 TOP50 합계는 5000입니다. TEST 실험식 LogPower_95는 일반 LogPower와 별개입니다.

POINT는 API의 `rating`을 사용하며 TOP50 합계가 Tier에 반영됩니다. 과거 POINT는 Score·MAX COMBO 여부와 패턴 최대치로 추정하므로 API 원본과 차이가 날 수 있습니다.

DJPower는 BASIC 상위 70패턴과 NEW 상위 30패턴을 따로 선발합니다. 이론상 최대 TOP100 합계가 10000이 되도록 보정합니다. TEST RATE의 개별 DJPower 열은 보정 전 값을 표시하고, 합산에는 보정을 적용합니다.

현재 DJPower는 곡 API의 `newTab`을 참조합니다. 과거 NEW는 해당 시점의 DLC·개별 곡 출시일을 복원합니다. 2025-09-11 이후 규칙은 출시 후 6개월이며, 6개월이 지난 곡은 다음 업데이트 시점에 NEW에서 제외됩니다. RV/CP 예외 곡은 지정된 출시일을 우선 사용하고, 없으면 최초 패턴 난이도 이력으로 추정합니다. 실패·빈 응답은 12시간 후 재시도합니다. `Permutation Part.1`(829)은 PLI2 분류지만 2026-09-03 개별 추가일을 사용합니다.

히스토리의 과거 floor·패턴 최대치가 완전하게 복원되는 것은 아닙니다. 현재 카탈로그 정보와 추정 수식을 사용하는 부분이 있으므로 과거 게임 화면의 합계와 정확히 같다는 보장은 없습니다.

## TEST 추가 기능

- 추천 기록 갱신과 오늘의 연습
- 닉네임별 관리, 성장 가이드, Floor 분석, 실험실, 행이봇_tags
- 시점 비교의 분 단위 범위와 변경된 기록 필터
- 종합의 데이터 상태·백업/복원·30일 성장 요약·카탈로그 변경 보고서
- NEW 복원 집합과 API 집합의 누락·초과 비교 진단

TEST에서 성장 가이드, Floor 분석, 실험실, 로페봇 및 행이봇_tags는 테스트 전용 표시를 따릅니다. 브라우저/PWA에는 데스크톱 전용 히스토리 수집 기능이 제공되지 않습니다.

### 추천 기록 갱신

기본 가중치는 `ln(1 + 경과일) / sqrt(max(1, 히스토리 횟수))`입니다. 오래된 기록의 우선순위를 높이고, 갱신 이력이 많은 기록의 우선순위를 낮춥니다. floor 평균 이하 모드는 기본 가중치에 `(floor 평균 - Score) / 표준편차`를 곱하며 평균 이하인 기록만 표시합니다. 통계는 같은 버튼·floor의 기록을 기준으로 계산합니다.

버튼·floor·Score 범위를 지정할 수 있고, Score 100 이상은 추천하지 않습니다. 추천 목록의 **갱신 실패**는 시도 시각을 저장하고 계산상 히스토리 횟수를 1 늘립니다. API 기록이나 실제 히스토리 이벤트를 변경하지 않습니다.

### 오늘의 연습

추천 기록 갱신 탭에서 버튼·floor·Score 범위와 곡 수를 정하고 **오늘의 연습 만들기**를 누릅니다. 1~30곡을 지원하고 기본 10곡은 몸풀기 2곡, 갱신 도전 6곡, 마무리 2곡으로 구성됩니다. 다른 곡 수에서는 비율을 반올림하므로 구성별 개수가 달라집니다.

- 몸풀기: 낮은 floor와 오래된 기록을 우선합니다.
- 갱신 도전: 오래된 기록, floor 평균보다 낮은 기록, LP TOP50 진입 가능 및 남은 LP 상승 여지를 고려합니다.
- 마무리: Score 달성률이 높은 기록과 오래된 기록을 우선합니다.

선정 이유를 각 곡 옆에 표시합니다. **LP TOP50 진입 가능**은 99.9에서 얻을 수 있는 LP가 현재 진입선보다 높다는 뜻이며, 필요한 Score가 현재 Score와 가깝다는 보장은 아닙니다. 오늘의 연습은 추천 목록의 가중치를 그대로 사용하지 않고 위 구성별 기준으로 따로 선발합니다.

같은 곡은 버튼·패턴이 달라도 세트에 한 번만 포함합니다. 후보가 부족하면 가능한 개수만 생성합니다. **교체**는 같은 구성에서 현재 큐에 없는 다른 곡을 고릅니다. 대기 중인 큐를 새로 생성할 때는 교체 확인을 받습니다.

**성공·실패**는 연습 큐에 시도 시각과 결과를 저장합니다. API Score와 히스토리 횟수는 변경하지 않습니다. 같은 패턴을 최근 24시간 안에 시도했거나 갱신했다면 생성 가중치를 0.15배로 낮춥니다. 추천 목록의 **갱신 실패**와 연습 큐의 **실패**는 별도 기능입니다.

큐는 닉네임별·일반판/TEST별로 로컬 저장합니다. **완료 항목 정리**는 성공·실패 항목을 삭제하므로 해당 항목에 저장된 최근 시도에 따른 우선순위 조정도 사라집니다. 기존 공용 큐는 닉네임별 큐에 자동 이관하지 않습니다.

### 데이터 상태와 백업

종합의 **상태 다시 계산**에서 프로필·히스토리·공통 데이터·설정의 대략적인 용량과 NEW 구성 대조를 확인합니다. 데스크톱에서는 필요한 RV/CP 출시일 이력을 조회할 수 있습니다. 조회가 불가능하거나 출시일이 없는 경우 NEW 진단이 불일치할 수 있습니다.

백업은 JSON 파일로 프로필, 히스토리, 공통 캐시, 설정과 연습 큐를 내보냅니다. 계정 연결 정보와 토큰은 제외합니다. 백업에는 닉네임과 기록이 포함되므로 공유 전에 내용을 확인하세요. 복원은 현재 채널의 IndexedDB 데이터를 백업 내용으로 교체하고 화면을 다시 엽니다. 일반판과 TEST 간 자동 동기화 기능은 아닙니다.

30일 성장 요약의 LP 증가는 상승한 개별 패턴의 LP 증가량 합계입니다. TOP50 합계 증가량과 같지 않습니다. 30일 전 기준 기록이 없는 패턴은 제외합니다. 곡 목록 변경 보고서는 마지막으로 감지한 변경을 최대 500패턴까지 보관합니다.

## 구조

웹앱과 데스크톱 앱 모두 기록 데이터를 사용자 환경에서 V-ARCHIVE API로 직접 요청합니다. 호스팅 서버는 정적 화면 파일, 버전 정보와 데스크톱 배포 ZIP만 제공합니다.

```text
호스팅 서버 -> 사용자: HTML, CSS, JavaScript, 업데이트 파일
사용자 -> V-ARCHIVE: 기록 및 히스토리 API
사용자 -> djmax.gg: 자켓 이미지
사용자 환경 -> IndexedDB/localStorage: 기록 캐시와 설정
```

일반 기록 조회는 닉네임 기반 공개 API를 사용합니다. 기록 히스토리는 데스크톱 앱에서 사용자가 선택한 `account.txt`의 회원번호와 토큰으로 V-ARCHIVE에 직접 로그인한 뒤 요청합니다. 앱 설정에는 토큰이 아닌 `account.txt` 경로만 저장되고 로그인 쿠키는 앱 메모리에서만 유지됩니다.

## 실행

### 웹

정적 파일은 `web/`에 있습니다. 로컬 서버를 사용할 때는 저장소 루트에서 다음 명령을 실행합니다.

```powershell
python web_server.py
```

브라우저에서 `http://127.0.0.1:8787/`을 엽니다.

### 데스크톱

Node.js, Rust와 Windows WebView2가 필요합니다.

```powershell
npm install
npm run desktop:dev
```

릴리스 빌드:

```powershell
npm run desktop:build
```

실행 파일은 `src-tauri/target/release/v-archive-viewer.exe`에 생성됩니다.

## 배포 채널

- `test` 브랜치는 푸시할 때마다 개인 검증용 Windows ZIP과 `test-latest` 프리릴리스를 만듭니다. 앱 옆에 `TEST.txt`가 있으면 개발자 확인 업데이트를 받고, 파일을 지우면 공개 업데이트 채널로 돌아갑니다.
- `main` 브랜치는 변경 검증만 자동 실행합니다. 공개 웹, GitHub Release와 업데이트 매니페스트는 `Build, release, and deploy` 워크플로를 수동 실행할 때만 갱신됩니다.
- 테스트가 끝난 변경은 `test`에서 `main`으로 PR을 합친 뒤 공개 배포합니다.
- 정식판은 의미 버전(`v0.1.52` 등), TEST는 빌드 번호로 업데이트 여부를 판단합니다. TEST 빌드의 표시 버전이 정식판보다 낮아도 빌드 번호가 높으면 TEST 업데이트 대상입니다.
- 중요한 수정만 정식에 먼저 반영할 수 있으므로 두 브랜치의 모든 기능이 항상 같지는 않습니다.
- TEST ZIP은 빌드별 고유 이름을 사용하고 크기·SHA-256 검증 후 매니페스트를 공개합니다. 정식 배포도 ZIP 검증 후 웹 업데이트 정보를 공개합니다.

검증 명령(TEST 기준):

```powershell
npm ci
npm test
npm run validate:app
npm run tags:validate
npm run build
cargo test --manifest-path src-tauri/Cargo.toml
```

`validate:app`은 현재 TEST 브랜치에서 제공하는 구조 검사입니다. 정식 브랜치에서는 해당 스크립트가 없을 수 있습니다.

## 데이터와 개인정보

- 기록, 히스토리와 UI 설정은 사용자 환경에 저장됩니다.
- `account.txt`, 회원번호와 로그인 토큰은 저장소나 호스팅 서버로 전송되지 않습니다.
- 데스크톱 앱은 업데이트 확인을 위해 배포 서버의 작은 버전 JSON을 요청합니다.
- 자동 업데이트 파일은 다운로드 후 크기와 SHA-256을 검증합니다.

`account.txt`의 첫 줄 형식:

```text
회원번호 로그인토큰
```

이 파일은 절대 Git에 커밋하지 마세요.

## 문제 해결

- 기록 누락: 버튼·패턴·검색·floor 필터를 확인한 뒤 일반 새로고침, 필요하면 전체 새로고침을 사용합니다.
- 히스토리 수집 불가: 데스크톱 앱인지, 조회 닉네임과 account.txt 계정이 같은지 확인합니다. 웹/PWA에서는 로그인 기반 수집을 지원하지 않습니다.
- NEW 합계 불일치: 기록 새로고침 후 성장 기록을 다시 엽니다. TEST에서는 종합의 상태 다시 계산으로 누락·초과 곡을 확인합니다.
- 앱 실행/업데이트 문제: Windows ZIP의 `v-archive-repair.bat` 복구 도구를 사용합니다. 캐시 초기화는 기록·설정을 지울 수 있으므로 가능한 경우 먼저 백업합니다.
- 업데이트 파일 크기/해시 불일치: 업데이트 확인을 다시 실행합니다. 검증을 무시하고 파일을 설치하지 않습니다.

이 프로젝트는 V-ARCHIVE, DJMAX 또는 NEOWIZ의 공식 프로젝트가 아닙니다. 각 서비스와 이미지의 권리는 해당 소유자에게 있습니다.
